## One OA-18 producer interface

OA-18 owns `.github/workflows/operational-assurance.yml` and the actual boundary
runner. The reserved immutable artifact name is `operational-assurance-boundary`.
Its ZIP contains exactly two root members: `boundary-receipt.json` and the
original OA-02 `release-plan.json` bytes. Raw logs and individual gate receipts
remain in a separately retained full packet. No caller-provided JSON or
`approved` field establishes provenance.

OA-18 reuses the schema and `release_evidence.py`; it must not invent a second
certificate format. The module exposes `SCHEMA_VERSION`, `SCENARIOS`, `PACKAGES`,
`ARTIFACT_NAME`, `BOUNDARY_WORKFLOW`, `canonical`, `sha256`, `validate_policy`,
`validate_receipt`, `validate_preparation`, `verify_candidate_tag`, `validate_run`,
`validate_approvals` and `fetch_boundary`. Only `fetch_boundary` establishes
remote provenance and returns `(receipt, preparation_plan, provenance)`;
content validators alone cannot authorize local data. Canonical hashing is
UTF-8 sorted-key compact JSON with one trailing newline.

The exact receipt fields are `schema_version`, `purpose`, `candidate`,
`contract_digest`, `tag`, `tag_object`, `version`, `manifest_sha256`,
`preparation_plan_sha256`, `tag_verification`, `scenarios`, `baseline`, `review`,
`operator_gates` and `status`. Full lowercase commit/tag-object IDs and exact
version `0.4.0` are required. The producer hashes its checked command/environment
manifest and the uploaded original preparation-plan bytes. Its actual OA-03
tag result plus `public_trust_sha256` must equal the consumer's fresh real
verification result; the top-level tag object must agree as well.

Each OA-01 through OA-17 occurs exactly once. Scenario, baseline, independent
review and G-02/G-03/G-04 records have status; PASS requires the digest of the
actual observed receipt. Scenario records also identify their scenario ID.
The producer must derive these from real retained evidence, never dispatch
input statuses. G-01 rotation/KBD signer replacement is deferred/non-blocking;
G-05 is independently established on the current publication run/environment.

| Packet purpose | Required status and observations | Allowed consumer effect |
|---|---|---|
| `rehearsal` | Global `NOT_EXERCISED`; individual records may be PASS with actual receipt digests or `NOT_EXERCISED` | Exercise nonpublishing tooling only |

## Independent provenance and publication controls

The consumer accepts a numeric server artifact ID, not a receipt file or
arbitrary API origin. Authenticated fixed-origin GitHub reads establish the
artifact name/ID, server archive SHA256, freshness/expiry, repository/fork
identity, successful completed run, exact full candidate, `main`, exact approved
workflow path, `workflow_dispatch` event and operator-pinned workflow contents.
Environment ID/name and authorized reviewer user IDs must match actual approval
history. A missing remote collaborator returns BLOCKED/exit 2; invalid evidence
returns FAIL/exit 1. Neither is passing evidence.

Both source and publication runs must be first attempts. The official review
schema provides environment/state/user/comment but no approval timestamp or
run-attempt binding. Since rerun approval history could belong to an earlier
attempt, reruns are rejected; a fresh separately approved dispatch is required.
Pending/rejected/ambiguous matching histories also fail. This restriction does
not substitute for reviewing actual environment protection/settings.

The public policy comes from protected `RELEASE_TRUST_POLICY_JSON`, never a
dispatch receipt or artifact. It pins repository/main/version, both workflow
SHA256 values, adopted contract digest, positive environment/reviewer IDs,
bounded freshness and public signature trust. The template is deliberately
unarmed. Approved runner-local public trust must already exist. SSH binds exact
principal/fingerprint and allowed-signers/effective revocation bytes. OpenPGP
binds the approved primary fingerprint and existing public `pubring.kbx` or
`pubring.gpg` bytes; keyboxd-only homes are unsupported. No whole home/private
key is read or copied to construct a public digest.

Workflow tooling is checked out separately at `github.workflow_sha`; candidate
data is checked out with full history and without persisted credentials. Only
after independent candidate signature/trust authorization does the gate load
that candidate's actual OA-02 manifest checker. The original plan's pre-bump
source candidate must be an ancestor of the frozen candidate; its exact file
digests bind final manifests, lockfile, changelog and release policy. The plan
must list exactly core, runtime-tokio, pg, embedded, iggy, wasm and facade, all
at the lockstep version, excluding the unpublished FFI crate.

Preparation has no publisher/OIDC permission. Rehearsal has contents/actions
read only and invokes no Cargo. The explicit `publish` operation alone reaches
`release-crates-io` with contents/actions read plus `id-token: write`. Before
OIDC, `--mode authorize` requires certification and the current active approved
first-attempt main-branch release run at the same frozen candidate. The final
`--mode publish` repeats these checks. The pinned official action's per-step
temporary output is the sole registry credential; there is no long-lived
secret/cached credential fallback. CLI environment variables alone do not prove
token provenance; the pinned trusted workflow and actual approved run supply
that authority.

Publication uses a fresh Cargo home and an allowlisted child environment:

```bash
cargo publish --workspace --exclude prometheus-parking-lot-ffi --locked --registry crates-io
```

The gate records intent before invocation. A partial publication failure needs
operator inspection and a fix-forward decision; there is no automatic retry.
The fixture never supplies OIDC or executes the real publication command.
