## Exact contract and APIs

The result idempotency identity is `(storage namespace, complete MailboxKey,
caller key)`. All tenant/user/session fields participate; `None` differs from
`Some("")`. First-write-wins survives consume/reopen until the original fence
expiry; a no-TTL fence is permanent. Other addresses have independent fences.
Unkeyed storage and `DeliveryOutcome::{Stored, Duplicate}` are unchanged.

`ResultMailbox<T>` method signatures remain unchanged. The shared core exports
`LegacyIdempotencyOwner { idempotency_key: String, key: MailboxKey }` with
`new(caller_key, key)` and serde/unknown-field rejection. The actual public path
is `prometheus_parking_lot_core::LegacyIdempotencyOwner`, also available through
that crate's contracts module; no facade `core::backend` export was added.

| Backend | Actual entry point |
| --- | --- |
| PG | `PgResultMailbox::<T>::migrate(pool: &PgPool).await -> Result<(), SchedulerError>`; empty owner mapping. |
| PG explicit | `PgResultMailbox::<T>::migrate_with_idempotency_owners(pool: &PgPool, owners: &[(String, LegacyIdempotencyOwner)]).await -> Result<(), SchedulerError>`; outer string is exact `mailbox_name`. |
| Embedded ordinary | `EmbeddedStore::open(path)` / `open_with_clock(path, clock)` create/reopen schema 2 and refuse schema 1. |
| Embedded explicit | `open_with_idempotency_owners(path, owners: &[LegacyIdempotencyOwner])` / `open_with_clock_and_idempotency_owners(path, clock, owners)` convert schema 1 explicitly or validate a schema-2 replay. |

Embedded paths retain `impl AsRef<Path>` and clocks `impl Clock + 'static`;
they return `Result<EmbeddedStore, SchedulerError>`. PG invalid/insufficient
ownership evidence currently returns `SchedulerError::Internal`, database
failures `Backend`; embedded invalid layout/mapping returns `InvalidConfig`,
storage failures `Backend`. There is no mapping-file CLI or config-builder
owner-evidence mechanism. Configuration builders use ordinary migrate/open.

The runbook is the ADR's section **Operational runbook: isolated rehearsal and
future store conversion**. It contains typed caller examples and the mapping,
quiescence, backup, replay and rollback sequence.

## Implemented schemas, inference and replay

PG protocol 2 uses `pl_result_mailbox_v2`,
`pl_result_mailbox_keys_v2 (mailbox_name, mailbox_key, idempotency_key)` and
`pl_result_mailbox_protocol`. Original `pl_result_mailbox`,
`pl_result_mailbox_keys` and old sequence state remain provenance; copied v2
results preserve native values/order and the sequence high-water mark.
`pl_result_mailbox_owners_v2` retains resolved legacy ownership independently
of active TTL fences. Actual legacy table names remain occupied and statement
triggers reject INSERT/UPDATE/DELETE/TRUNCATE with SQLSTATE `55000`. Frozen 005
startup may complete, but cannot remove those guards or create another writable
old namespace. Read-only inspection of retired tables is not old-reader support.

Embedded keeps `mb_entries`, `mb_meta` and all queue tables/counters/identity.
`mb_idem_v2` is the structured `(canonical MailboxKey JSON, caller key)` fence
table. Original `mb_idem` and resolved-owner `mb_legacy_owners_v2` are retained
as immutable provenance. The schema marker `q_meta.schema_version = 2` is
committed atomically with conversion, so the frozen schema-1 open rejects it.

Initial conversion infers an active fence owner only from one retained row
matching namespace, caller key and exact original expiry generation. PG uses
native `IS NOT DISTINCT FROM` timestamp comparison; embedded compares original
millisecond expiry with the permanent sentinel. No candidate requires
authoritative consumed-owner evidence. Multiple exact-generation candidates
require an authoritative mapping selecting one candidate, never an unrelated
address. Duplicate, unknown, expired or conflicting initial assignments fail.
Unresolved active owners refuse atomically with logical tables/schema/identity
unchanged. Expired ownerless fences stay immutable legacy records with no
invented owner or active global effect.
