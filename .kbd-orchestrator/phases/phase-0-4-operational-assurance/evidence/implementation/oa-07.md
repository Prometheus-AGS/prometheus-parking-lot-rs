## Exact public contract and backend APIs

`DeliveryOutcome` is `Stored` or `Duplicate { status: TaskStatus }`, deriving
Debug/Clone/PartialEq/Eq and losing Copy/Hash. Stored is still a unit variant.
Duplicate returns original full status/error atomically with suppression, even
after consume, for the original fence lifetime. It does not replace results,
read payloads/destructively consume to discover status, extend TTL or return
retry status. Missing/undecodable metadata is an error. ResultMailbox method
signatures and OA-06 `(storage namespace, complete MailboxKey, caller key)`
scope remain intact; None and empty identifiers remain distinct.

Memory retains `{ status, expires_at }` separately from consumable results.
StorageMailbox forwards outcomes unchanged and notifies only Stored. FFI's
existing two-way DeliveryResult intentionally uses `Duplicate { .. }` and
omits metadata rather than substituting local status.

Core exports `LegacyDeliveryStatus { idempotency_key: String, key: MailboxKey,
status: TaskStatus }` and `new(caller_key, key, status)`, with serde and unknown
field rejection. `LegacyIdempotencyOwner` remains separate and asserts no
status. Actual public paths are `prometheus_parking_lot_core` and its contracts
modules; no facade export is added solely for examples.

## Final schema, coherent evidence and runbook

The complete operational sequence is [ADR0007](../../../../../docs/adr/0007-authoritative-duplicate-status.md#operational-runbook-for-final-schema-3).
All source-1 owner conversion, status conversion and protocol-marker writes
share one transaction for direct 0.3 -> 3. Intermediate 2 -> 3 is equally
atomic; do not commit an intermediate owner migration before status refusal.

Infer only from the same retained generation: namespace, complete canonical
address, caller key and exact native original expiry. PG uses native timestamp
precision and `IS NOT DISTINCT FROM`; redb uses original milliseconds and the
permanent sentinel. A stale expired result with reused caller is not proof.
For schema 1, unknown owners require LegacyIdempotencyOwner; status records
cannot silently replace owner evidence. Schema 2 already has scoped addresses,
and status identities include those addresses. Multiple retained candidates
require authority selecting a coherent candidate owner/status, never borrowing
one row's owner and another row's status. Identical repeated proof can establish
one value. No candidates requires original authority. Missing/unknown/duplicate/
expired/wrong-address/contradictory initial assignments refuse atomically.

| Backend | Active state | Retained provenance and writer rejection |
| --- | --- | --- |
| PG17/18 | `pl_result_mailbox_v3`, `pl_result_mailbox_keys_v3` with status JSONB and native forget_at; protocol singleton version 3 | `pl_result_mailbox_metadata_v3` immutable status/expiry proof; `pl_result_mailbox_owners_v2` ownership proof; original/v2 results/fences/sequence state preserved and retired mutation triggers reject INSERT/UPDATE/DELETE/TRUNCATE with SQLSTATE 55000. |
| redb | `mb_entries`, `mb_meta`, `mb_idem_v3` structured address/caller -> status/forget-at JSON; `q_meta.schema_version = 3` | `mb_idem`, `mb_idem_v2`, `mb_legacy_owners_v2`, `mb_legacy_metadata_v3` retained; frozen schema-1 and schema-2 open protocols reject 3. |

PG holds advisory/table locks during conversion and preserves native result
rows/order and identity-sequence high-water. Old names stay occupied; startup
SQL may succeed but cannot recreate a writable old namespace. New keyed
delivery retains the claim row lock through fresh-statement metadata SELECT
and commit, handling a concurrent winner without same-statement snapshot loss.
Redb keeps raw result bytes, timestamps and queue state/counters/identity under
one conversion transaction. Ordinary redb open supplies no implicit conversion.

After conversion, empty mapping reopen succeeds. Nonempty replay validates
immutable owner/status provenance, including after consume/expiry/eviction;
it cannot recreate fences, extend TTL or overwrite a newer generation.
Unknown/conflicting/duplicate replay refuses. Expired unmatched source rows
stay immutable provenance, not active suppression or invented status.

For any future identified store: stop old handles, take a consistent untouched
backup, record SHA-256/schema/namespace/native precision/queue identity and
bind authoritative mappings to that exact source. Rehearse only an isolated
copy via Rust metadata APIs; never execute SQL 008/009 separately. Preserve
refusal logical snapshots and original backup bytes. After conversion run
only new readers/writers. Rollback stops new writers and restores the untouched
pre-upgrade backup to a separate target; converted stores cannot be safely
downgraded. Reconcile subsequent writes separately. Archived PG readability
is inspection, not supported old-reader use. Redb transaction refusal promises
logical rollback, not byte-identical physical housekeeping; backup bytes are
retained independently. No live upgrade occurred or is authorized here.

## Supported statuses and runtime settlement

Mailboxes preserve all current statuses: Queued, Running, Completed,
Failed(full TaskError), Expired and Dropped(original reason). They do not
acquire an unrelated terminal-only validation rule. Durable duplicate settlement
uses original status for both the event and resolution:

| Original status | Normal durable action |
| --- | --- |
| Completed | Completed event; ack. |
| Failed(error) | Failed event containing original error.to_string(); dead-letter with that reason. |
| Expired | Expired event; deadline dead-letter. |
| Dropped(reason) | Rejected(Custom(reason)); dead-letter original reason. No fabricated historical CapacityExceeded. |
| Queued/Running/unsupported future | Existing warning/Requeued hand-back; no invented terminal result, ack or dead-letter. |

Normal order is mailbox delivery/duplicate status -> reported/terminal event ->
heartbeat stop -> selected lease resolution -> held-work finish. Exhausted
mailbox errors retain the existing requeue path. No mailbox address keeps local
classification. Retry/backoff, oversize threshold, shutdown/cancellation,
permit release, OA09 rejected handling and OA10 expiry remain preserved.
Local success/failure counters continue describing execution attempts.
A finite nonterminal fence retains its original TTL; a permanent nonterminal
fence can retry indefinitely until a separate explicitly authorized remediation.
