## Final-boundary exact invocations

Run only at oa-18 task2 after implementation is complete and the candidate is
frozen. Supply existing absolute local executable paths in `RELEASE_PLZ_BIN`
and `GIT_CLIFF_BIN`, full lowercase candidate/base SHAs, an explicit ISO date
and a fresh evidence output outside the source checkout. The base must be an
ancestor of the candidate. Python 3.11 or newer, Git, the pinned Rust toolchain
and required caches must already exist. No global installation is authorized.

The adopted regression entry point is:

```bash
python3 scripts/release/test-preparation.py \
  --source "$PWD" --candidate "$CANDIDATE_SHA" --base "$BASE_SHA" \
  --version 0.4.0 --date "$RELEASE_DATE" \
  --release-plz "$RELEASE_PLZ_BIN" --git-cliff "$GIT_CLIFF_BIN" \
  --output "$EVIDENCE_DIR/oa-02"
```

It executes the real preparation twice. It retains
`oa-02/prepared/workspace`, `release-plan.json`, first/second tool command logs
and each mismatch invocation's exact argv/exit/stdout/stderr. Required success
is exactly seven package versions, consistent sibling dependency requirements
and lockfile entries, seven release changelog subsections, FFI exclusion and
unchanged second-run artifact hashes/plan bytes. Each deliberately broken
control must fail at its specific policy diagnostic; a missing tool, compiler
failure or syntax error cannot satisfy a negative control.

For standalone use of the same production path at that boundary:

```bash
python3 scripts/release/prepare.py check --workspace "$PWD"
python3 scripts/release/prepare.py prepare \
  --source "$PWD" --candidate "$CANDIDATE_SHA" --base "$BASE_SHA" \
  --version 0.4.0 --date "$RELEASE_DATE" \
  --release-plz "$RELEASE_PLZ_BIN" --git-cliff "$GIT_CLIFF_BIN" \
  --output "$PREPARATION_DIR"
```

Use a separate fresh `PREPARATION_DIR`. The script also accepts a rerun of the
same exact input tuple in its own existing output, to exercise actual repeated
tool execution. `set-version` invokes Cargo metadata and a workspace lockfile
refresh, so serialize it with other Cargo work. Package builds, upload dry-run
rehearsals and the broader phase packet remain the final runner's responsibility.
