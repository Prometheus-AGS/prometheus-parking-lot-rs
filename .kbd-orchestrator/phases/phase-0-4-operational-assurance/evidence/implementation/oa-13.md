The vector fixture uses the real public pool with six total units, CPU ceiling
three and VRAM ceiling two. A CPU+VRAM task holds three total units; a second
waits behind the full VRAM dimension while a CPU-only two-unit task runs. The
assertions require actual peak five total/two VRAM, the intended start order,
oversized VRAM rejection and released units after retrieval. The existing
scalar fixture separately requires overlap without crossing its total ceiling.

Budget and retrieval scenarios use the production `sleep`/JS timer path and
`spawn_local` pool. Deterministic `TestClock` advancement is limited to the
deadline decision in parked-expiry cases; dispatch, JS event-loop progress,
result settlement and event delivery still use the real pool. Browser durable
lease/ack/mailbox expiry is inapplicable because this pool has no durable backend.
