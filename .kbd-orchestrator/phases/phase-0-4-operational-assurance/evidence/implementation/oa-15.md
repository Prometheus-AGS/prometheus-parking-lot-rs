## Final-boundary argv and owned filesystem control

Invoke these from the repository root, after the **whole** production/doc set
is frozen. Output/fixture directories are fresh and outside the checkout.
Run the build command separately on each actual supported native OS:

```bash
python3 bindings/tauri-desktop/assurance/desktop-assurance.py build --output "$NATIVE_BUILD_OUT"
```

The wrapper's actual production argv is
`cargo +1.99.1 build --manifest-path bindings/tauri-desktop/Cargo.toml --workspace
--bins --locked --message-format=json-render-diagnostics`. It records actual
compiler-artifact executable discovery, verbose Cargo/rustc/Python identities,
native platform/SDK/library identities, source/lock/protocol/contract/candidate
binding and the binary SHA256. A real successful receipt explicitly retains
GUI runtime NOT_EXERCISED. No build was run here.

The exact macOS fixture command forms are:

```bash
python3 bindings/tauri-desktop/assurance/desktop-assurance.py prepare \
  --case positive --build-receipt "$MAC_BUILD_OUT/build-receipt.json" --parent "$EXTERNAL_FIXTURE_PARENT"
python3 bindings/tauri-desktop/assurance/desktop-assurance.py prepare \
  --case delete-store-control --build-receipt "$MAC_BUILD_OUT/build-receipt.json" --parent "$EXTERNAL_FIXTURE_PARENT"
python3 bindings/tauri-desktop/assurance/desktop-assurance.py launch --root "$PRINTED_ROOT"
python3 bindings/tauri-desktop/assurance/desktop-assurance.py capture \
  --root "$PRINTED_ROOT" --stage first-processed --image "$ACTUAL_BEFORE_IMAGE"
python3 bindings/tauri-desktop/assurance/desktop-assurance.py capture \
  --root "$PRINTED_ROOT" --stage second-collected --image "$ACTUAL_AFTER_IMAGE"
python3 bindings/tauri-desktop/assurance/desktop-assurance.py classify --root "$PRINTED_ROOT"
```

These are forms, not a single executable sequence: follow the runbook for the
two actual launch sessions and human UI actions for each independently prepared
root. Use the tool's printed synthetic input and canonical root, never guessed
IDs/paths. The source wrapper does not submit/process/collect through a mock or
headless service; a human uses the incumbent visible controls and quits fully.

Only in the deletion-control root, after the first closed successful process
and before the second launch:

```bash
python3 bindings/tauri-desktop/assurance/desktop-assurance.py delete-store --root "$CONTROL_ROOT"
```

This deletion is the narrowly adopted G-06/OA-15 negative control at the real
filesystem boundary. It checks the marked private case/nonce/candidate/root,
source identity, closed process receipt, actual first submit/process/local-page
trace, no active/unresolved child, nonempty regular store and unchanged digest.
It records intent and unlinks exactly `store/parking-lot.redb` inside that root.
No recursive deletion, profile deletion, glob, arbitrary target or production
app-data lookup is provided. The fixture's incognito webview storage is separate
from the explicit durable test file. No store/root/profile has actually been
created, opened or deleted by these authored instructions.

Missing prerequisites/captures/GUI platform are BLOCKED where explicitly
classified (exit 2). Observed build/trace/source/assertion failures are FAIL
(exit 1); the deletion control requires its exact missing-result failure and
supporting actual deletion/empty-collect evidence, not any nonzero exit. Native
launch/display failures must retain raw reasons and unavailable G-06 access
must remain BLOCKED in the final packet. Never replace it with PASS from a build.
