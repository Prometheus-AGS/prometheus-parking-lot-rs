## Verification and authorization boundary

The candidate must be a complete lowercase commit object ID, not an abbreviated
revision. The exact short tag name resolves only under `refs/tags/`. Its object
must be an annotated tag whose signed header directly names the frozen commit,
type `commit` and the same internal tag name. Lightweight tags, nested tag
targets, renamed tag objects and a different commit are not authorized.
Replacement objects are disabled. Git verifies the captured immutable tag
object, and the ref must still resolve to it afterward.

SSH mode requires the exact approved principal **and** full SHA256 public-key
fingerprint. An operator-provided public allowed-signers file supplies trust;
an optional explicit revocation file may be supplied, and an existing configured
revocation file is not suppressed. Verification uses Git/OpenSSH's complete
trusted success line under the C locale, not a tag message or key comment.

OpenPGP mode uses an existing approved GnuPG home and a full approved primary
fingerprint from `VALIDSIG`. A signing subkey is allowed only under that primary
identity. UID/email text and local ownertrust are not authorization substitutes.
Git's crypto result must succeed; bad, missing, expired or revoked signature/key
status is rejected separately. The wrapper disables options-file loading,
automatic discovery/lookup, agent startup and automatic trustdb checking. It
imports or generates no keys and changes no global trust settings.

These guards address the explicit unsigned/wrong-identity/wrong-commit scenario
and the named signature/ref/trust boundary. Unexpected verifier output or tool
errors fail; the code emits no raw tag payload or private material.

Primary sources read during task 1:

- [Git verify-tag](https://git-scm.com/docs/git-verify-tag) documents real tag
  signature verification and raw verifier output.
- [Git signing configuration](https://git-scm.com/docs/git-config) documents
  OpenPGP/SSH programs, minimum trust, allowed signers and revocation files.
- [Git's SSH parsing source](https://github.com/git/git/blob/master/gpg-interface.c)
  defines the trusted principal/fingerprint success line used by Git itself.
- [OpenSSH ssh-keygen](https://man.openbsd.org/ssh-keygen) documents signature
  verification, allowed principals, revocations and fingerprint reporting.
- [GnuPG status DETAILS](https://github.com/gpg/gnupg/blob/master/doc/DETAILS)
  defines `VALIDSIG` signing and primary fingerprints and failure statuses.
- [GnuPG configuration options](https://www.gnupg.org/documentation/manuals/gnupg/GPG-Configuration-Options.html)
  document the verification wrapper's controls; [key-management commands](https://www.gnupg.org/documentation/manuals/gnupg/OpenPGP-Key-Management.html)
  document the fixture's future temporary primary/subkey generation.

These documentation reads are not execution evidence. Local tool versions and
runtime compatibility remain unverified.

## Workflow public trust configuration

The reusable workflow takes `candidate`, `tag` and an existing approved `runner`
label. It requests only `contents: read`, fetches full refs without persisting
checkout credentials and uses `release-signature-verification` as its environment.
Default-branch and environment protection must be established by the operator;
their existence or protection was not inspected or configured by this task.

| Operator environment variable | Meaning |
|---|---|
| `RELEASE_SIGNATURE_FORMAT` | `ssh` or `openpgp` |
| `RELEASE_SSH_IDENTITY` | Independently approved exact SSH principal |
| `RELEASE_SSH_FINGERPRINT` | Independently approved full SHA256 fingerprint |
| `RELEASE_SSH_ALLOWED_SIGNERS` | Public allowed-signers text, never a private key; written only to the job's temporary file |
| `RELEASE_SSH_REVOCATIONS_FILE` | Optional existing runner-local public revocation file |
| `RELEASE_GPG_FINGERPRINT` | Independently approved full OpenPGP primary fingerprint |
| `RELEASE_GPG_HOME` | Existing absolute runner-local approved verification home with required public keys |

There is no production key-import or key-generation step. OpenPGP on an
unprovisioned hosted runner cannot pass; an existing approved verification home
is required. No runner, account/environment setting, identity or public trust
file was provisioned by this worker. The default-branch verifier must first be

## Final-boundary commands and sixteen classifiers

Only after the complete phase implementation set, the boundary runner executes:

```bash
bash .github/scripts/tests/release-tag-fixtures.sh
```

This command requires real Git, Python 3, ssh-keygen, GnuPG and gpgconf. At that
future invocation only, the fixture creates two temporary SSH identities and
two temporary OpenPGP primary identities with signing subkeys. Public identities
are `approved-fixture@example.invalid` and `other-fixture@example.invalid`.
Both SSH keys are trusted by the fixture file, so wrong-identity rejection must
come from explicit authorization rather than a missing public key. The same
distinction holds for OpenPGP keys in its isolated home. The fixture uses no
host signing-agent socket or host trust store, imports/copies no private key,
creates no real release tag and contacts no remote. Cleanup addresses only its
own GPG home/agent and temporary root; cleanup failure makes the suite fail.

Within that fixture, the positive and negative classifier command forms are:

```bash
python3 "$verifier" --tag "$fixture_tag" --candidate "$candidate" "${ssh_args[@]}"
python3 "$verifier" --tag "$fixture_tag" --candidate "$candidate" "${gpg_args[@]}"
```

`ssh_args` is exactly `--format ssh --identity approved-fixture@example.invalid
--fingerprint "$ssh_fp" --allowed-signers "$fixture_root/allowed-signers"`.
`gpg_args` is exactly `--format openpgp --fingerprint "$gpg_fp" --gnupg-home
"$gnupg_home"`. All IDs/fingerprints are resolved from the real temporary
repository/keys at invocation, never prefilled with guessed or release values.
The fixture prints the fully expanded argv, working directory, actual exit
and public metadata log for each case.

## Candidate and public trust receipt binding

The verifier's PASS JSON contains `tag`, `tag_object`, `candidate`, `format`,
`identity` and `signing_fingerprint`. The final boundary must join that observed
JSON to the full frozen candidate, adopted contract digest, verifier/wrapper/
fixture/workflow content digests, actual tool/executable versions, environment,
exact argv/exit, timestamps and raw public-metadata stdout/stderr. Capture the
suite's emitted logs outside its temporary root before cleanup.

Also bind an operator-approved **public trust configuration digest** to that
receipt. For SSH, include format, exact principal/fingerprint, allowed-signers
bytes and effective revocation-file bytes/configuration, including an existing
configured revocation file if no explicit override was passed. For OpenPGP,
include the approved primary fingerprint and public verification-key snapshot
with signing subkeys and revocation state. The operator supplies/approves that
public snapshot; do not export, hash wholesale or attach a GnuPG home containing
private keys, private-key files, agents or credentials. Preserve the approved
trust snapshot used at invocation and reject a changed/stale digest.

The verifier JSON does not itself calculate this trust/configuration digest or
prove operator approval; the oa-18 boundary packet must supply that binding.
Fixture-generated identities only establish the tooling path. They cannot
replace the independently approved real release identity or make G-03 PASS.
